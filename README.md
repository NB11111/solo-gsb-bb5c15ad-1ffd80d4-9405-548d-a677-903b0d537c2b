# 换气接力 · 合唱排练 Web 应用

在统一的秒轴时间线上安排各声部歌手的换气区间，实时检查“同时发声人数是否达标”，
并对选中的换气段在 ±N 秒内**穷举最优移动方案**，预览修复前后差异。

纯前端实现（React + TypeScript + Vite），数据保存在浏览器 `localStorage`，无需后端。

## 一键启动（Docker Compose）

```bash
docker compose up -d --build
```

启动后在浏览器访问：

> **http://localhost:8080**

停止：

```bash
docker compose down
```

## 本地开发（不用 Docker）

```bash
npm install
npm run dev        # http://localhost:5173
```

生产构建与本地预览：

```bash
npm run build
npm run preview    # http://localhost:4173
```

## 使用说明

1. **添加声部 / 歌手**：工具栏“添加声部”，声部标题栏“添加歌手”；可重命名、设置声部颜色标识。
2. **设置最低发声人数**：每个声部标题栏设置 `最低发声 N 人`——任意一秒该声部正在发声
   （即没有在换气）的歌手数不得低于此值。
3. **安排换气区间**：
   - 双击歌手行空白处：新建一段 2 秒换气区间；
   - 拖动色块中部：移动（自动吸附整数秒，并自动避开该歌手自己的其他换气段）；
   - 拖动色块左右边缘：调整时长；
   - 也可在右侧检查器中直接编辑起止秒数。
   - 所有时间都是**整数秒**，区间一律采用**半开区间 `[start, end)`**，区间端点相接
     （如 `[2,5)` 与 `[5,8)`）不算重叠。
4. **实时覆盖计算**：
   - 每条声部有一条“覆盖”行，某一秒换气人数超过 `歌手总数 − 最低发声人数` 时，
     该时段**合并并标红**；
   - 每个歌手行上也有淡红遮罩；
   - 顶部“全曲未达标”条汇总任一声部不足的时段（并集）；
   - 状态栏显示**全曲未达标总秒数**（各声部不足秒数之和）及每个声部的不足秒数。
5. **穷举最优修复**：点击选中一个换气段，在右侧面板设置搜索范围 `±N 秒`，
   系统枚举范围内所有整数起点，要求**保持时长不变且不与该歌手其他区间重叠、
   整体位于全曲范围内**，并依次按以下规则排序：
   1. 应用后全曲未达标总秒数最少；
   2. 相对当前位置的位移量最小；
   3. 仍平局时取更早的时刻。
   表格中点击任意候选可预览，下方展示修复前后各声部队不足时段的迷你对比图与总秒数变化，
   点击“应用移动”生效。
6. **示例数据**：点击工具栏“载入示例”可加载一个 40 秒、三声部（女高/女低/男高）、
   每声部 4 人最低 3 人发声的示例。其中女高声部张三的 `[10,13)` 与王五的 `[11,14)`
   在 11–13s 换气撞车导致不足；选中张三该换气段并以默认 ±5 秒穷举，最优解为移到
   `[8,11)`（与王五区间端点相接，位移仅 2 秒），全曲未达标总秒数由 2 降为 0。
7. **保存**：所有修改自动保存到浏览器本地（`localStorage`）；也可用“导出/导入 JSON”
   归档或与他人分享工程。

## 算法要点

- 覆盖按**逐秒计数**：对每个声部建立长度为总时长的数组，统计每秒正在换气的人数，
  再把数值相同的相邻秒**合并**为连续半开区间；换气人数 `> 歌手总数 − 最低发声人数`
  的区间即为标红的不足时段。
- 拖动落点用“自由窗口”法求距离目标起点最近的合法整数位置（平局取更早）。
- 穷举直接枚举 `[curStart−N, curStart+N]` 内的全部整数起点，过滤越界与本人区间重叠者，
  对每个候选整体重算全曲未达标总秒数，按三级规则排序。
